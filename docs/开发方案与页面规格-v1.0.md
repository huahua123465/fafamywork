# 个人项目展示站 · 开发方案与页面规格

版本：v1.0（待审核）  
日期：2026-09-07  
当前阶段：需求与设计确认，尚未开始前端实现。

## 1. 审核摘要

建设一个面向大学生的个人项目展示网站，以商城式浏览方式展示开发者自己的作品。访客能够发现项目、了解用途和实现思路，并进入可用的在线演示。

视觉以用户已认可的第二版设计稿为基准：浅灰白背景、大留白、黑色大标题、蓝色按钮、柔和色彩项目封面。参考苹果的视觉层级与产品介绍方式，保留自己的名称、内容和品牌。

本方案将“这个项目相关的页面”理解为完整展示站，包括首页、全部项目、项目详情、关于我和联系入口。“关于我”单独设计成完整页面。第一版不包含购物车、支付、订单、账号系统、评论、管理后台和项目本身的业务功能。

下列项目为本次审核的重点；批准本文表示同意其作为第一版实现范围。尚缺真实素材不影响页面结构开发，但上线前需要确认内容。

| 审核项   | 建议方案                                               |
| -------- | ------------------------------------------------------ |
| 产品定位 | 个人作品展示，商城式浏览，不做交易                     |
| 页面范围 | 首页、全部项目、详情页模板、关于我、404；共用联系弹窗  |
| 技术选型 | TypeScript + Vue 3 + Vite + Vue Router + 原生 CSS      |
| 数据来源 | 本地类型化内容文件，第一版无后端                       |
| 视觉方向 | 沿用已确认的第二版设计稿，并扩展其他页面               |
| 内容原则 | 用户提供的真实资料优先；示例必须标明；不虚构经历和成果 |
| 实施顺序 | 文档审核 → 页面开发 → 交互与视觉验收 → 发布方案确认    |

## 2. 开发语言与技术选型

### 2.1 语言与框架的区别

| 技术                  | 类型                           | 在网站里的用途                                  |
| --------------------- | ------------------------------ | ----------------------------------------------- |
| HTML                  | 标记语言                       | 标题、正文、导航、图片、表单等结构              |
| CSS                   | 样式语言                       | 颜色、字体、留白、布局、响应式和动效            |
| JavaScript            | 编程语言                       | 浏览器里的交互逻辑                              |
| TypeScript            | 增加类型检查的 JavaScript 语言 | 在开发阶段检查数据和代码，构建后输出 JavaScript |
| Vue / React / Angular | 框架或 UI 库                   | 组织组件和页面，不是开发语言                    |

常规 Web 前端以 HTML、CSS、JavaScript 为基础；现代工程经常使用 TypeScript 编写逻辑。这里不按市场份额给框架排名。

### 2.2 本项目建议

- Vue 3：使用单文件组件与 Composition API，将页面模板、逻辑、样式组织在一起，适合本项目规模和后续维护。
- TypeScript：约束项目分类、图片、链接、个人资料等数据结构，减少字段遗漏。
- Vite：本地开发与生产构建。实施时选择相互兼容的稳定版本，记录 Node 版本并提交依赖锁文件。
- Vue Router：页面路由、浏览器前进后退和直接访问详情页。
- CSS：通过统一设计变量和可复用组件实现视觉；不套用管理后台组件库的默认外观。
- 数据与状态：本地内容文件、路由查询参数、Vue 原生状态即可；第一版不引入全局状态库。
- 图标与字体：使用许可清晰的 SVG 图标和系统中文字体栈，不依赖远程字体加载；图标统一尺寸和笔画。

React + TypeScript 同样可行；本次选择 Vue 是基于项目复杂度和模板可读性的工程判断，不是浏览器能力上的限制。若你更希望学习 React，可在审核阶段替换选型。

## 3. 用户与内容策略

目标访客是大学生，但不能因此假设你的真实项目都是校园工具。设计稿中的课表、校园搭子和灵感收集夹仅是样式示例，真实项目确定后调整分类和介绍。

访客主要任务：

1. 快速判断这里展示哪些作品。
2. 根据用途寻找感兴趣的项目。
3. 看清项目解决什么问题、怎么使用、由谁完成。
4. 进入真实演示、查看公开源码或联系作者。

文案先说明用途和实际功能，技术栈放到详情页次要位置。无依据时不展示用户量、评价、奖项、上线时间和性能提升等数字。

## 4. 信息架构与路由

| 页面/入口  | 路径                    | 核心目标                         |
| ---------- | ----------------------- | -------------------------------- |
| 首页       | `/`                     | 建立印象，展示精选作品，引导探索 |
| 全部项目   | `/projects`             | 分类、搜索、排序和浏览           |
| 项目详情   | `/projects/:slug`       | 了解用途、功能、界面和实现过程   |
| 关于我     | `/about`                | 了解作者、能力和创作经历         |
| 联系弹窗   | 各页面顶部的联系入口    | 展示已确认的联系渠道             |
| 未找到页面 | 不存在的路径或项目 slug | 解释问题并提供返回入口           |

主导航：首页使用“探索”，另有“全部项目”“关于我”，右侧搜索与“联系我”。当前页面明确高亮。搜索入口跳转项目列表并聚焦搜索框。

## 5. 页面详细规格

### 5.1 首页

从上至下：

1. 顶部导航：个人站点名称或标识、主要页面入口、搜索和联系按钮。轻微半透明仅用于导航背景，保证文字可读。
2. 首屏介绍：一句核心主张、简短补充说明、“探索全部项目”和“关于我”两个入口。示例标题不能自动视作最终文案。
3. 精选项目视觉：一个主项目预览搭配最多两个辅助预览，使用真实截图或明确标注的示例图。图片不是包含所有按钮的整张页面背景。
4. 项目发现区：标题、用途分类、最多六个公开项目卡片，以及“查看全部项目”。分类切换只过滤本区；空分类显示友好提示。
5. 作者介绍条：一句介绍、头像或中性图形、创作故事入口，跳转关于我。
6. 页脚：站点名称、导航和已提供的社交入口；备案信息仅在适用且用户提供后显示。

项目卡片包括用途分类、名称、一句话介绍、封面、“了解项目”和可选“在线体验”。卡片不嵌套可点击按钮：标题与封面可进入详情，独立体验链接负责外跳。

### 5.2 全部项目

顶部为“全部项目”标题与一句说明，下方展示搜索、用途分类、排序和结果数。

- 搜索字段：项目名称、短介绍、分类和关键词；去除输入前后空白，英文忽略大小写。
- 搜索使用约 200 毫秒防抖；回车立即应用。搜索与分类组合生效。
- 排序：默认精选优先，其次按配置顺序；“最近更新”按真实更新时间倒序，无日期的排最后。
- 查询状态写入 URL：`q`、`category`、`sort`，方便分享和返回。搜索输入更新使用 replace，避免每次输入占一条历史记录。
- 每次显示十二个结果，“加载更多”追加十二个；条件改变后重置显示数量。
- 无结果显示“暂时没有找到相关项目”和“清除筛选”；项目总数为零时显示独立的内容待更新提示。
- 从详情返回列表时，尽可能恢复筛选、已展开数量和滚动位置。

### 5.3 项目详情

采用产品介绍式阅读顺序，所有项目共用同一套模板，由内容数据决定显示哪些模块。

1. 面包屑：全部项目 / 当前项目。
2. 介绍区：分类、项目名、核心用途、真实状态、可用的演示与源码入口。
3. 大幅预览：主图和缩略图切换；无图时显示统一占位，不出现破图。
4. 项目概览：为谁做、解决什么问题、核心价值，保持短段落。
5. 主要功能：三至六个功能点，每项包括名称、具体说明、可选截图。
6. 界面展示：截图说明和放大查看；图库支持上一张、下一张、键盘方向键与关闭。
7. 设计与开发：需求背景、关键设计决策、本人职责、遇到的问题和解决方法。技术栈在这里展示。
8. 基本信息：平台、项目类型、更新时间等，仅渲染实际提供字段。
9. 使用说明：进入方式、演示限制、必要的公开演示账号说明；不在静态文件中放私密账号、令牌和密钥。
10. 相关项目：优先同类别，最多三个，不重复当前项目。
11. 底部行动区：再提供真实可用的体验入口与联系作者按钮。

缺少源码时隐藏源码入口；缺少演示时显示“演示暂未开放”，保留介绍阅读。没有支持内容的模块整段隐藏，不生成虚构文字。

### 5.4 关于我（完整独立页面）

页面目标：让同学理解你是谁、在做什么、作品由你承担哪些部分，以及怎样联系你。

1. 个人首屏：真实昵称/姓名、头像、身份短句、两至三句介绍；主要按钮“看看我的作品”，次要按钮“联系我”。未提供头像使用中性图形。
2. 创作故事：两到三个短段，解释做项目的起点、关注的问题、持续创作的方向。由用户提供事实，协助润色。
3. 我能做什么：按实际能力展示，如界面设计、前端开发、交互实现；配具体作品证据。不使用无依据的百分比能力条。
4. 我的创作过程：理解需求 → 草图与设计 → 开发与验证 → 迭代维护。此处是待用户确认的介绍模板，不能默认宣称为真实经历。
5. 项目与经历时间线：只展示已确认的事件、日期和角色；没有资料时隐藏整个模块。
6. 代表作品：最多三个真实作品卡片，进入各自详情页。
7. 联系区：邮箱、GitHub、其他公开渠道，由用户选择公开内容。简历下载仅在提供文件并确认公开后出现。

桌面端首屏左右分栏，正文控制阅读宽度；手机端头像与介绍纵向排列。个人资料由独立内容文件维护，不散落在模板中。

### 5.5 联系弹窗与 404

联系弹窗展示真实渠道，支持复制邮箱或微信号、打开公开主页；不做没有服务端接收能力的留言表单。复制成功才显示成功提示；失败时提供可选中文本。未配置渠道时明确显示暂未提供联系方式。

弹窗打开后焦点进入弹窗，支持 Escape 关闭、焦点约束，关闭后回到触发按钮。微信二维码支持在弹窗内查看，只有取得素材后显示。

404 页使用统一视觉，显示“这个页面暂时找不到”，提供“回到首页”“浏览项目”；无效项目 slug 也进入此状态。

## 6. 视觉与响应式规则

| 项目     | 设计基准                                                   |
| -------- | ---------------------------------------------------------- |
| 主背景   | `#FFFFFF`，分区背景 `#F5F5F7`                              |
| 正文     | 主色 `#1D1D1F`，次色 `#626269`                             |
| 操作色   | 蓝色 `#0066CC`；链接和按钮状态统一                         |
| 圆角     | 卡片约 24px，小控件约 12px，主按钮胶囊形                   |
| 内容宽度 | 最大约 1200px，详情正文约 760px                            |
| 字号     | 首屏桌面约 56–72px、手机约 36–44px；正文 16–18px           |
| 间距     | 以 8px 为基础，主要区块间距桌面约 80–112px、手机约 48–64px |
| 动效     | 以 160–240ms 淡入、颜色、微小位移为主                      |

数值属于实现基准，可为匹配设计稿适度微调。浅色封面内的文字仍需保持足够对比度。

- 1024px 及以上：完整导航，项目卡片三列。
- 768–1023px：项目卡片两列，导航与首屏适度收缩。
- 低于 768px：折叠菜单、卡片单列、介绍区纵排；分类允许横向滚动，页面本身无横向溢出。
- 手机首屏保留一个清晰主预览，辅助窗口重排或减少，避免缩成不可读小字。
- 交互目标尽量不小于 44 × 44 CSS 像素；hover 效果不是获得关键信息的唯一方式。
- 尊重系统减少动态效果设置；不使用自动播放轮播、强制滚动或滚动劫持。

## 7. 内容数据与维护方式

计划使用 TypeScript 内容文件，静态图片独立存放。新增项目时添加一个项目条目和对应图片，无需复制详情页组件。

| 数据对象 | 必要字段                                              | 可选字段                                                         |
| -------- | ----------------------------------------------------- | ---------------------------------------------------------------- |
| 站点     | 名称、简介、导航配置                                  | 标识、社交渠道、备案信息                                         |
| 作者     | 显示名称、简短介绍                                    | 头像、故事、能力、经历、公开联系方式、简历                       |
| 项目     | id、唯一 slug、名称、分类、短介绍、概览、状态、排序值 | 封面、图库、功能、技术栈、演示 URL、源码 URL、真实日期、精选标识 |
| 图片     | 文件地址、替代文本                                    | 图注、宽高                                                       |
| 功能     | 名称、说明                                            | 关联截图                                                         |

项目状态建议限定为“可体验”“开发中”“已归档”；技术状态不自动决定链接是否可用。开发示例使用独立的示例标识，页面显式提示，不与真实项目混淆。

项目详情文字用结构化段落渲染，第一版不直接注入任意 HTML。外部链接只允许预期协议，邮箱和其他联系方式使用各自对应的入口。

## 9. 质量与部署约束

- 每个页面设置正确标题、描述、语义化标题层级，图片提供有意义的替代文本。
- 第一版为客户端渲染静态站点。路由使用 history 模式，部署平台需将非文件请求回退到入口 HTML；直接访问项目详情需要验证。
- 客户端动态 meta 不保证所有社交爬虫都能抓取。若搜索收录或每个项目的分享预览是核心要求，应在开发前改为预渲染或静态生成方案。
- 首屏关键图片按显示尺寸处理，其余图库按需或延迟加载；声明图片尺寸以减少布局跳动。
- 公开内容会被下载到浏览器，不能存放任何私密资料。普通外链使用清晰的外跳标识与合适的安全属性。
- 本轮不部署。审核后实现，发布时根据实际平台补充部署配置与上线步骤。

## 10. 实施与验收计划

### 阶段 A：审核与内容确认

确认本文件范围、技术选型和个人资料公开范围。收集真实项目资料。未齐全时可先用明确标注的示例实现布局。

### 阶段 B：视觉与页面实现

先完成设计变量、导航页脚、首页和项目卡片，随后完成列表、详情、关于我、联系弹窗与 404。各页面沿用已认可的视觉，不另换风格。

### 阶段 C：行为验证与内容替换

验证组合筛选、URL 状态、前进后退、列表恢复、图库、复制行为和缺失内容的展示。替换真实资料并清理示例提示。

### 阶段 D：交付审核

提供可本地预览的网站、完整源码、运行说明、内容维护指南与验收记录。说明尚缺的资料和未验证的外部条件。

验收清单：

- [ ] 首页符合已认可的浅色设计方向，整体比例、留白和视觉层级一致。
- [ ] 首页、列表、详情、关于我、404 可直接访问，浏览器前进后退正常。
- [ ] 搜索与分类组合、排序、清空筛选、加载更多、无结果状态均正确。
- [ ] 所有可见按钮有清晰且真实的行为；没有链接的入口不会伪装成可体验。
- [ ] 关于我的故事、技能、经历和联系方式基于用户提供事实。
- [ ] 详情图库切换、放大、关闭可用，图片缺失有明确兜底。
- [ ] 联系弹窗键盘可操作，复制失败与成功提示符合实际结果。
- [ ] 在 375px、768px、1024px、1440px 宽度下没有页面横向溢出、重叠或截断。
- [ ] 在可用的 Chrome/Edge 环境实际检查；Safari/iOS 如无测试环境，在记录中明确待验证。
- [ ] 页面无本项目引起的控制台错误、破图和站内死链。
- [ ] 类型检查、生产构建通过；搜索逻辑、路由和关键访问流程通过适度自动化或浏览器验证。
- [ ] 核查文字对比度、键盘焦点和减少动画设置，记录检查结果。
- [ ] 交付时说明真实内容完成度，不将功能开发完成等同于已具备上线内容。

# 用户分享积分系统部署与回滚

## 上线前说明

本次更新增加普通用户账号、SQLite 数据库、分享积分和管理员积分控制。公开资料、留言和访问统计原有 JSON 文件继续保留，新增数据库位于：

```text
/root/fafamywork/deploy/data/app.db
```

API 现在使用项目内的 Dockerfile 构建，不再把 `deploy/api` 目录直接挂载进通用 Node 容器。第一次部署需要执行 `--build`。

## 环境要求

- Docker 和 Docker Compose 可用。
- `/root/fafamywork/deploy/data` 可写并已作为持久化目录保留。
- `deploy/.env` 中已有 `ADMIN_PASSWORD` 和 `TOKEN_SECRET`。
- `TOKEN_SECRET` 必须长期保持不变；更换后会影响安全摘要和现有管理登录凭证。
- 不需要预先创建 `app.db`，API 启动时会自动初始化表结构和默认积分规则。

## 首次部署

在服务器执行：

```bash
cd /root/fafamywork
git pull --ff-only origin main
npm install
npm run build
cd deploy
docker compose up -d --build api
docker compose up -d web
docker compose ps
```

检查 API：

```bash
curl -fsS http://127.0.0.1:8080/api/health
```

预期返回：

```json
{"ok":true}
```

然后检查：

- 首页和项目列表可以直接浏览。
- 项目详情存在“分享赚积分”。
- `/account` 可以打开且未登录时显示登录提示。
- `/admin` 登录后可以看到“用户与分享积分”。
- `deploy/data/app.db` 已生成。

## 日常更新

如果后续修改涉及 `deploy/api`：

```bash
cd /root/fafamywork
git pull --ff-only origin main
npm install
npm run build
cd deploy
docker compose up -d --build api web
```

仅修改前端时仍可以执行同一组命令，确保静态文件和 API 版本一致。

## 数据备份

部署前先创建备份目录并复制持久化数据：

```bash
cd /root/fafamywork
mkdir -p deploy/backups
docker compose -f deploy/compose.yml stop api
cp -a deploy/data "deploy/backups/data-$(date +%Y%m%d-%H%M%S)"
docker compose -f deploy/compose.yml start api
```

停 API 后复制可以确保 SQLite 主文件和 WAL 文件处于一致状态。备份内容包括：

- `app.db`：用户、会话、分享记录、积分流水和管理员审计。
- `profile.json`：站点资料。
- `messages.json`：买家留言。
- `stats.json`：访问统计。
- `media/`：上传的二维码等媒体。

不要把 `deploy/data` 或备份文件提交到 Git。

## 恢复数据

确认要恢复的备份目录后执行：

```bash
cd /root/fafamywork
docker compose -f deploy/compose.yml stop api
mv deploy/data "deploy/data.before-restore-$(date +%Y%m%d-%H%M%S)"
cp -a deploy/backups/选定的备份目录 deploy/data
docker compose -f deploy/compose.yml start api
docker compose -f deploy/compose.yml ps
```

恢复后检查 `/api/health`、普通用户登录和管理员后台。

## 代码回滚

先找到需要回滚到的提交号，然后使用可追溯的反向提交：

```bash
cd /root/fafamywork
git log --oneline -10
git revert 要回滚的提交号
npm install
npm run build
cd deploy
docker compose up -d --build api web
```

不要使用 `git reset --hard`，也不要强制推送。

如果旧版本 API 不认识新数据库，可以保留 `app.db`，旧版本不会读取它；不要直接删除数据库。需要恢复旧数据状态时，使用部署前备份。

## 常见问题

### API 容器无法启动

```bash
cd /root/fafamywork/deploy
docker compose logs --tail=100 api
```

重点检查：

- `.env` 是否存在并包含两个必需变量。
- `/root/fafamywork/deploy/data` 是否可写。
- Node 镜像是否成功构建。
- 服务器是否有足够磁盘空间。

### 登录正常但积分不增加

在管理员后台检查：

- 分享积分是否开启。
- 每日奖励次数是否已达到上限。
- 有效停留秒数是否设置过高。
- 当前用户是否被停用。
- 同一访客是否仍处于去重周期。

积分只在访客通过带 `ref` 的专属链接进入、达到停留时间并产生真实交互后发放。点击分享按钮本身不会发积分。

### 数据库文件越来越大

SQLite 使用 WAL 模式，运行时可能出现 `app.db-wal` 和 `app.db-shm`，属于正常文件。备份时应停 API 后复制整个 `deploy/data` 目录，不要只复制单个数据库文件。
